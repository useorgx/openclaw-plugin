# G0.3 Discovery: MCP Result UX Polish (2026-02-24)

Artifact type: audit
WCAG target: AA
Scope: MCP tool-result rendering in Mission Control activity detail surfaces

## Assumptions
- This slice is discovery-only for milestone `G0.3`, not implementation.
- Demo-script coverage should prioritize the highest-frequency outputs first (text, JSON object, list, nested object, and fallback/no-output states).

## Evidence from Code
1. Tool-result extraction can degrade to a generic fallback string, which loses meaning for users:
- `src/local-openclaw.ts` (function `extractText`) returns `[tool result]` when no text blocks are extracted from a `tool_result` payload.

2. Activity detail supports structured and JSON views for artifacts, but structured object rendering currently summarizes nested structures as counts instead of showing key content:
- `dashboard/src/components/activity/ActivityTimeline.tsx` (`renderArtifactValue`) renders nested objects as `N fields` and arrays as `N items` in structured mode.

3. Artifact payload extraction already checks MCP-relevant keys (`toolOutput`, `toolOutputs`, `toolResult`, `toolResults`), providing a stable insertion point for polish changes:
- `dashboard/src/components/activity/ActivityTimeline.tsx` (`extractArtifactPayload`).

4. Markdown rendering supports links/code/tables/headings, so rich text is already viable once payload normalization is improved:
- `dashboard/src/components/shared/MarkdownText.tsx`.

## UX Risks (Triage)
| Severity | Risk | User Impact | Evidence |
|---|---|---|---|
| major | Generic `[tool result]` fallback | Users cannot tell what the tool returned, reducing trust and debuggability | `src/local-openclaw.ts` |
| major | Structured mode collapses nested object details | Users must switch to raw JSON for important values, increasing cognitive load | `ActivityTimeline.tsx: renderArtifactValue` |
| medium | Inconsistent readability across payload types | Demo quality drops when mixed payloads appear during live verification | `extractArtifactPayload` + `renderArtifactValue` |

## Demo-Script Coverage Matrix (Tool-by-Tool)
Use this matrix for G0.2/G0.3 verification passes.

| Case | Example payload shape | Expected 10/10 rendering bar |
|---|---|---|
| A | plain string | Rendered as readable markdown block with preserved links/code formatting |
| B | flat object | Key/value table with direct values, not only counts |
| C | nested object | Expandable nested sections showing important leaf values |
| D | array of objects | Per-item cards with key values visible at first glance |
| E | missing/empty tool result | Friendly fallback copy with context (tool name or event type), not generic token |

## Verification Steps (for implementation follow-up)
1. Open Mission Control activity detail view and select an item with a tool payload mapped through `extractArtifactPayload`.
2. Validate structured mode against matrix cases A-E.
3. Validate JSON mode still shows full raw payload.
4. Confirm no regression in markdown rendering for string payloads (links, tables, code blocks).
5. Confirm fallback message contains context and never shows raw `[tool result]` token.

## Recommended Acceptance Criteria for G0.3
- No generic placeholder text for tool results in user-facing detail panes.
- Structured mode surfaces meaningful nested content (not only aggregate counts).
- JSON mode remains available and parity-safe for debugging.
- All matrix cases A-E are demoable in one scripted flow.
